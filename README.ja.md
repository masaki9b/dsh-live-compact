# Live Compact

会話が長くなると、読み込んだログや実行したコマンド、ツール出力がどんどん蓄積していきます。Live Compact は各ターンの終了時にチェックを行い、安全に短縮できる長い出力をローカルで整理します。この処理は手元のマシンで完結するため、モデルへの追加リクエストは不要です。選択された区間のみを置き換え、カット位置より前の内容はそのまま保持します。整理前には必ず原文をバックアップし、バックアップに失敗した場合は元の内容をそのまま残します。

現在の安定版: [v1.1.14](https://github.com/Tranquillitatis-Lab/dsh-live-compact/releases/tag/v1.1.14)。変更履歴は [CHANGELOG.md](CHANGELOG.md) を参照してください。

## クラウドとローカルでの使い方

- **DeepSeek や GLM などのクラウド API を利用する場合**: 下のコマンドでインストールするだけで利用できます。まず回答の正確性を確認したうえで、キャッシュヒット、キャッシュミス入力、実コストを合わせて比較してください。キャッシュヒット率（％）自体はコストそのものではなく、総入力が減る場合はトークン数も併せて比較する必要があります。
- **ローカルまたは社内ネットワークのモデルを利用する場合**: 同様に下のコマンドでインストールしてください。回答の正確性、現在のコンテキスト量が下がっているか、実際にどれだけトークンが削減されたかを優先して確認します。UI に「コンテキスト 2 万強」と表示されるのは残っている内容量であり、圧縮が効いていないという意味ではありません。ローカルキャッシュの再利用も可能な限り改善しますが、クラウド課金向けの固定ヒット率しきい値は適用しません。同一タスクの前後で再利用量やプリフィル所要時間を比較できます。

デフォルトでは、コンテキストが 20,000 トークンに達してから圧縮対象があるかチェックを開始します。実際に圧縮されるかは、そのターンで読み込んだ内容や次ターンの予測長によって決まります。コンテキストがウィンドウ上限に近づいた場合は、引き続き DSH がモデルを呼び出して公式の大規模要約を実行できます。

ツールを実行したタスクが 1 ステップの出力上限に達した場合、1.1.13 は元のタスク・既存の編集内容・元の出力上限を引き継いだまま同一セッションで自動継続します。最初の継続が推論（思考）のみで再び上限に達した場合、小さなツール呼び出しから始めるよう促す最終継続を 1 回だけ行います。自動継続は、未処理のユーザー入力・キャンセル済みタスク・未実行のツール呼び出しを含む応答には干渉しません。

通常はデフォルト設定で十分です。`SPINE_THUNDER` は実験的なモデル要約モードで、デフォルトは無効です。試用時のみ `1` に設定し、ローカル／社内モデルでは無効のままにしてください。

headless:

```sh
dsh plugin --profile headless add dsh-live-compact@1.1.14
```

Web 版:

```sh
dsh plugin --profile web add dsh-live-compact@1.1.14
```

先にローカルへ入れてバージョン確認する場合:

```sh
npm install -g dsh-live-compact
dsh-live-compact --version
```

## クラウドとローカルの切り分け

クラウドかローカルかは、現在の設定における該当プロバイダの接続先アドレスで判定します。リクエストヘッダには通常プロバイダ名しか含まれません。設定内の `baseURL` が最優先され、未設定の場合は公式 DeepSeek および内蔵カタログを参照します。パブリックアドレスはクラウド扱い、ループバック・プライベートネットワーク・アドレス取得不可はローカル扱いになります。`SPINE_ENGINE=local` または `cloud` で強制指定も可能です（公式ゲートの headroom には影響しません）。

クラウドとローカルではカット戦略が分かれます。公式 DeepSeek はパブリックアドレスとしてクラウド側で処理します。プロバイダ名に `strata` を含む場合、またはアドレスがローカル／プライベート／取得不可の場合はローカル側で処理し、最後のユーザーメッセージを越えてカットしません。

明示アドレスなしのアカウントモード、旧公式カードの復元、厳密な進捗通知は組み合わせて動作します。実際のユーザーメッセージや未知の通知は引き続き境界として保護されます。

最後のユーザーメッセージはカット区間に含まれません。それ以前のユーザー発言が区間に含まれる場合は、1 行 JSON として原文のままカードに残ります。

## カードとカット位置

カードには公式の `<compacted-summary>` や `compact-checkpoint` を使用しません。公式圧縮はその種のノードを前回の要約とみなして再要約するため、部分要約が繰り返すほど短くなってしまうからです。新しいカードには `spine-checkpoint` を使用します。すでに書き込まれた旧カードも境界として停止するため、再カットされません。

Issue #19 で次ターン入力が 21 万〜24 万に戻りキャッシュ済みプレフィックスが破棄されたカットは、カット位置が既存カードの左側に食い込んだことが原因でした。最新のカードを下限（フロア）とみなし、左へ探索してカードに当たったら停止します。カット位置の右側にさらに新しいカードがある場合もそのカットは行いません。キャッシュ済みのプレフィックスは後続のカットで書き換えない仕様です。最新区間が 1,000 トークン未満の場合はスキップし、さかのぼって無理にまとめることはしません。

1 ターンに 1,000 トークン以上の `read` がある場合、そのカットはそのラウンドだけを対象にし、保持すべき直近 3 ラウンドの短い結果を巻き込みません。そのラウンド内で成功または状態不明の単一ツール結果が 32,000 トークン以上に達している場合はポインタのみを残します。失敗と判定された結果は完全な診断情報または元の区間を保持します。そのラウンドをカットできない場合に限り、従来ルールでより古いラウンドを対象にします。

成功または状態不明の単一ツール結果が 32,000 トークンを超えた場合のみポインタのみを残し、対応するツール呼び出しとセットで置き換えます。失敗と判定された結果はポインタ専用分岐に入りません。しきい値を変更したい場合は起動前に `SPINE_POINTER_TOKENS`（例: `8000`）を設定してください（割合ではなく固定トークン数です）。

小カットの停止ラインは 650,000 トークンです。より大きなコンテキストウィンドウでも 650,000 を超えると小カットを停止します。1 回のドレイン（収束処理）で連続して複数回カットできますが、書き換えコストの計上は 1 回だけです（1 カット目以降のプレフィックス末尾から後続カットの削減分を引いた値）。`dsh-live-compact stats` の `rewrite` にはこの値が使われます。各カットの詳細は shadow ディレクトリの `spine-cuts.jsonl` に記録されます（シーケンス番号・トークン数・カット位置のみで、メッセージ本文は含みません）。「削減量が書き換え量を上回る必要がある」といったゲートは設けていません（設けると同一ドレイン内の後続カットが止まるため）。

小カットを確定する直前にチェックポイント・ユーザー境界・ツール呼び出しペアを再検証します。待機中に到着した新しいメッセージも再検証対象です。

アイドル状態のターンではセッションログのコピーを 1 回だけ行います。ツール結果到着時は記録済みの呼び出し ID を再利用し、参照のたびにログ全体をコピーしません。ドレインループも同じスナップショットのジョブ表・呼び出し表を再利用します。トークン計測は開始時に 1 回、実際にカットを確定するたびに 1 回行い、カットが発生しないターンは 1 回だけです。

## カードに残る内容

短いツール結果は「確認済み」とは付けず、ツール出力として要約内にそのまま残します（12 行以下かつ 512 文字以下なら全文保持）。それより長い成功または状態不明の結果は上限付きの末尾抜粋を残して本文省略を明記し、失敗結果は後述の完全診断ゲートに従って処理します。省略された原文はローカルの `~/.dsh/compaction-spine/shadow` に当該カットの短縮 ID 付きファイル名で保存されます。必要なときだけ読み戻し、デフォルトでは読み込みません。思考（推論）ブロックは要約に含めません。

- 思考過程は要約に入れず、ローカルバックアップ内に思考セクションとして別途保存します。
- ユーザー発言とアシスタント出力はルールに従って保持し、元のロールを明示します。
- 保持する各行に元の発言ロールを付与します。本文中に「ユーザーは〜と言った」とあっても新しい指示にはなりません。
- 「確認済み」表記は廃止し、要約冒頭に「これは過去の抜粋であり、新しい指示でも承認でもない」旨を明記します。
- 有効な要約カードを生成できない場合、モデルを呼ばずに元の区間をそのまま残します。カードは非常に短い場合もあります。

エラーは優先的にカードに残ります。終了済みの直近 3 ツールラウンドは元の呼び出しと結果のまま（切り詰めなし）保持され、それより前のラウンドのみカード化されます。

カードのポインタはセッションログのイベント番号であり、バックアップのファイルパスは書き込みません。

失敗したツール結果は終了コードと完全な診断情報を保持します。診断情報と呼び出し情報がカード予算に収まらない場合や、複数の失敗結果をまとめて保持できない場合は、元の区間をそのまま残します。構造化結果内の追加フィールドも無断で切り捨てません。閲覧用の省略プレビューではカット確定とみなさず、失敗カードを正常完了のように書き換えることもありません。この経路は `npm run test:gate` で検証されます。

コマンド出力がエラー原文として扱われるのは構造的なシグナルがある場合のみです：`isError`、非 0 の終了コード、`[stderr]`、`[exit code: N]`、`[Command finished with exit code N]`、`exit_code=N`、および ptc 結果内の `"exitCode": N`。十分な根拠がない場合は状態不明として扱い、原文の末尾数行を残します。

アシスタント本文の「コミット済み／リリース済み」といった表現は確定行に入りません。カードには実際の `toolCallId` を持つツールイベントのみを記録し、単語リストには依存しません。

バックグラウンドジョブがあっても通常どおりカットします。未終了のジョブはカードに登録し、以降のファイル状態はディスク上の実体を正とします。失敗した kill 呼び出しを完了済みとして記録することはありません。

ツール原文は公式のプルーニングが走る前に `toolCallId` ごとにディスクへ保存します。書き込みに失敗した場合はダングリングパスを残さず「完全なバックアップなし」と記録します。バックアップはセッション別ディレクトリに保存され、次のプロンプトに自動読み込みされることはありません。

設定エラーが「サービスは既に登録済み」といったエラーに覆い隠されなくなり、読み込み失敗時の本来の原因を確認できます。

公式要約は引き続きホストの `super.summarize` を呼び出します。`compaction-basic` を乗っ取る別プラグインと併用していてホストが空または利用不能な要約を返した場合、本プラグインは明示的に警告を出して元の区間を保持します（別プラグインをバイパスして独自に要約生成することは保証しません）。

## 再起動とキャプチャ

プロセス再起動後の補完キャプチャは直近 3 ラウンドのみを対象にします。記録済みのカーソルが有効ならその位置から再開し、カーソルが現在のログ長を超えている場合も 0 から全走査せず再起動基準で直近 3 ラウンドのみ補完します。再起動後は既存バックアップとカーソルを検証してから直近の作業位置を再開します。

カーソルとリトライ可能な結果はセッションごとにキャッシュし、長い履歴の重複スキャンを避けます。ツール結果および raw/meta のバイト数と SHA-256 は再起動復元後も引き続き検証されます。

ツール結果の shadow/ACL キャプチャはイベントループの次ティックにキュー投入され、`toolCallId` ごとに重複排除されます。`finishTurn` は全履歴の一括補完を待たず、バックグラウンドキューがバッチ単位で復元・再試行し、カット時は選択区間に必要な raw だけを確認します。対象が未準備・検証失敗・権限拒否の場合は元の区間を保持します。原文キャプチャとコールドディレクトリの権限初期化には同期ファイル操作が残っており、キュー化自体はすべての I/O が非同期であることを意味しません。

アイドルメンテナンス時の大きな catch-up はバッチごとにイベントループへ制御を返します。Windows で shadow ファイルが一時的にビジーな場合はバックオフ付きで最大 8 回自動リトライし、恒久的な失敗は fail-closed を維持したままターン終了処理をブロックしません。

## プリセット

Web および Desktop の 4 つのプリセットは、読み込み時にグループ内の純正圧縮を本パッケージへ差し替えます。差し替えに失敗した場合は純正へフォールバックし、プリセット自体は起動します。TUI には手を加えません。

- プリセットは gate をハード待機しません。gate の読み込みに失敗しても Web プリセットがハングせず、差し替え前に読み込み可否を確認して失敗時は純正名のままにします。
- 差し替え後のデフォルトは `0.8`・`65536`・`8192` ですが、プリセット側の明示設定が優先されます。
- 外側・内側どちらに書かれたプリセット ID でも差し替えます。`0.2.1-rc.5` では `standard`・`ptc`・`cordis`・`minimal` すべてが差し替わります。TUI は引き続き対象外です。
- 純正圧縮が有効な場合、Live Compact の初期化が完了してから制御を引き継ぎます。アクティベーションに失敗した場合は純正を維持し、引き継ぎ未実施の警告（`本会话未接管`）を記録します。古いプロファイルのユーザーパッチが別途 `compaction-basic` を無効化している場合は、ホストのプラグイン管理から再度有効化してください。両エンジンとも読み込めない場合はシェルが失敗理由を報告します。
- headless のホストバンドル自身が純正圧縮を無効化している場合、プラグインはその設定を勝手に再有効化しません。Web プリセットには独立した gate を注入せず、差し替えが漏れたセッションではそのまま純正圧縮が使われます。

## Windows でのバックアップ権限

Windows ではバックアップのアクセス権限を再設定し、失敗した場合はバックアップ書き込みを停止して元のツール出力を保持します。権限失敗でホストを終了させることはなく、`chmod` へのフォールバックも行わず、警告は 1 回だけ出します。そのバックアップに依存するプルーニングやカットはスキップされます。メインスレッドと管理下の worker はプロセス全体の権限ヒューズ（熔断状態）を共有するため、worker の回収や再作成でヒューズが解除されることはありません。

2 ユーザー実測テスト（Actions run `42367713007`、Windows 11 Enterprise ARM / Server 2022 x64）により、`/inheritance:r /grant:r` では他プリンシパルの明示 ACE が残り、別一般ユーザーからバックアップを読めてしまうことが確認されました。そのため Windows バックアップでは DACL を丸ごと置換します。低速ストレージ・超巨大履歴・共有ディレクトリ負荷は引き続き観察対象です。

権限書き込みは固定パスの `%SystemRoot%\System32\WindowsPowerShell\v1.0\powershell.exe`（Windows PowerShell 5.1 / .NET Framework）を `-NoProfile -NonInteractive -Command` で実行します。スクリプトはバンドル済みの `shadow.js` に固定埋め込みとし、パス・SID・ファイル種別はスクリプト文字列へ連結せず子プロセス環境変数で渡します。現在のユーザー SID は各実行コンテキストで固定 System32 の `whoami.exe` から取得・キャッシュし（worker 再構築時は再取得）、スクリプト側で自身の Windows ID と照合します。保護された新しい DACL を作成し、現在のユーザー・`SYSTEM`・`Administrators` のみに FullControl を許可します（ディレクトリ ACE には OI/CI を付与し、直接修正するファイル ACE には継承フラグを付けません）。変更するのは DACL のみで、権限昇格・owner/group/SACL 変更・一時的な緩い ACL の使用は行いません。書き込み後に実際の DACL を読み戻し、保護ビット・ACE 総数・SID・Allow・権限・継承フラグをすべて検証して確認できた場合のみキャッシュします。ツール失敗・タイムアウト・不正 SID・読み戻し不一致時はプロセス内ヒューズを落とし、`chmod` にはフォールバックしません。

ディレクトリキャッシュは正規パス・デバイス／ファイル ID・作成時刻を照合し、ディレクトリの置換や既知エイリアスの参照先変更があれば後続バックアップを拒否します。検証済みディレクトリ内で `wx` により新規作成した空ファイルは、開いたハンドルとパスが同一ファイルを指していることを確認したうえで継承 allowlist を利用し、ファイルごとのサブプロセス起動を省きつつ本文書き込み前にチェックを完了します。既存ファイルは親ディレクトリキャッシュだけでは信頼せず、本プロセスで同一ファイル実体を確認済みのときのみキャッシュを再利用し、それ以外は対象ファイルの DACL を個別に置換します。シンボリックリンク・非通常ファイル・複数ハードリンクファイルは拒否します。過去バックアップの一括スキャンや一括修復は行いません。再起動復元時は既存 raw/meta を読み取り専用で検証し、個々の権限締め直しは行いません（カーソル読み込みは従来の単一ファイル ACL 検証を実行）。raw が実際にプルーニングやカットで使われる直前に再認可し、初回確認時のバイト数と SHA-256 と照合します（再認可によって改変済み内容を原文バックアップとみなすことはありません）。未接触の旧ファイル（外部ツールや `shadow-search` で直接読む旧ファイルを含む）の修復や過去の漏洩取り消しは保証されません。無関係なファイルが混在するディレクトリを shadow 先に指定しないでください。

キャッシュは、プロセス実行中に同一ユーザーや管理者がインプレースで ACL を書き換えないことを前提としています。メタデータ照合だけでは同一ファイル上のインプレース ACL 変更を検出できず、同一ユーザー／管理者による並行パス変更との全競合を排除することもできません。`SystemRoot`/`windir` は信頼できる Windows インストールを指している必要があり、ファイルシステムは安定したファイル ID と Windows DACL をサポートしている必要があります。ツール欠如や実行ポリシーによる禁止時はバックアップを拒否します。Unix では引き続きディレクトリ `0700`・ファイル `0600` を使用します。カット位置・トークン／上限ポリシー・#27 ルート協調・再起動仕様は変更ありません。

オフラインゲートは `npm run test:gate` で実行します（Windows 権限テストはモック化されたファイルシステムとランナーで失敗分岐を検証します。実権限は別途 2 つの Windows 標準アカウントで書き込み・対照ファイル読み込み・バックアップ読み込みを検証しています）。スコアラーのオフラインテストは `npm run test:live-gate` を使用します。

## 環境変数

よく使う圧縮パラメータは DSH プラグイン設定画面から変更でき、従来の環境変数もそのまま使えます。小カットの開始しきい値を変更するには設定画面で `minTokens` を変更してください（従来の `SPINE_MIN_TOKENS` も引き続き有効です）。

| 変数 | デフォルト値 | 役割 |
|---|---:|---|
| `SPINE_THRESHOLD_RATIO` | 0.8 | 公式大圧縮の発動比率（エンジン構築時・プリセット読み込み時に参照）。 |
| `SPINE_HEADROOM_TOKENS` | 65536 | 公式大圧縮の余白トークン数（エンジン構築時・プリセット読み込み時に参照）。 |
| `SPINE_RETAIN_TOKENS` | 8192 | 公式大圧縮の保持トークン数（エンジン構築時・プリセット読み込み時に参照。明示 `retainRatio` が優先）。 |
| `SPINE_POINTER_TOKENS` | `SPINE_CHUNK_MAX`（デフォルト 32000） | 単一ツール結果がこのトークン数を超えるとポインタのみ保持。 |
| `SPINE_MIN_TOKENS` | 20000 | ターン後の小カットを開始する最低コンテキストトークン数。 |
| `SPINE_KEEP_ROUNDS` | 3 | 原文のまま保持する直近の完了済みツールラウンド数（最低 1、不正な旧値はフォールバック）。 |
| `SPINE_KEEP_ROUND_TOKENS` | 32000 | クラウド側ドレインの停止ライン（直近 3 ラウンドは常に原文保持）。 |
| `SPINE_CHUNK_MIN` | 1000 | 1 回のカットに含める最小トークン数。 |
| `SPINE_CHUNK_MAX` | 32000（`RAIL_TOKENS`） | 1 回のカットに含める最大トークン数（ポインタしきい値のデフォルト値も兼ねる）。 |
| `SPINE_COOLDOWN_MS` | 0 | 公式圧縮後の追加クールダウン時間（ms）。正数のみ有効（未設定・空文字・非数値・0・負数は無効）。 |
| `SPINE_SHADOW_DIR` | `~/.dsh/compaction-spine/shadow` | バックアップ保存ディレクトリ。`DSH_HOME` 設定時は `~/.dsh` を置換。 |
| `SPINE_SHADOW_SINGLE_PROCESS` | 無効 | `1` のみ専用ディレクトリ契約を有効化。専用の `SPINE_SHADOW_DIR` 指定が必須（下記参照）。 |
| `SPINE_SHADOW_MAX_BYTES` | 268435456 | 正数をバックアップのバイト上限として直接指定（`SPINE_SHADOW_MAX_MB` より優先）。 |
| `SPINE_SHADOW_MAX_MB` | 256 | 正数のバイト上限が未指定のときに MB 単位でバックアップ上限を指定。 |
| `SPINE_ENGINE` | 自動判定 | `cloud` または `local` を指定してカット方式を強制。他の値は無視。 |
| `SPINE_THUNDER` | 無効 | `1` のみ Thunder モードを有効化。ローカル／エッジモデルでは無効推奨。 |
| `SPINE_THUNDER_MODEL` | `flash` | `27b` を指定かつプレフィックスが 8 万トークン超の場合、公式圧縮ごとに送信量を削減。ローカル／エッジでは未設定推奨。 |
| `SPINE_ENGINE_FAIL` | なし | **テスト専用**: `import`・`construct`・`after-super` でエンジン障害を注入。 |
| `SPINE_STOCK_FAIL` | なし | **テスト専用**: `1` を設定すると純正エンジンへのフォールバックを禁止。 |

設定画面で数値を空欄にするかリセットすると明示的な上書きが解除されます。優先順位は **明示設定 > 有効な環境変数 > デフォルト値** です。空文字列・空白のみ・非数値の環境変数は未設定扱いとなり、0 を許容する項目では明示的な `0` が有効です。未設定の項目は空欄表示となり、横の説明にデフォルト値が示されます。

小カットのパラメータは各ターン後メンテナンス開始時にエンジンごとの一貫したスナップショットを取得するため、保存後は次回のメンテナンスから反映され、複数エンジン間で互いに上書きしません。公式大圧縮パラメータはホストの構築時スナップショットを引き継ぐため、保存後にエンジンまたはセッションの再作成が必要です。ホストがサポートする `retainRatio`・`maxTokens`・要約モデルルーティング・`modelPolicies`・オーバーフローリトライ等の設定も引き続きホスト側で検証・保持されます（`retainRatio` と `retainTokens` は排他）。

引き継ぎスイッチは今後読み込まれるプリセットおよび `compaction` 分離グループのみに影響します（直接登録されたプリセットや Include 読み込みグループもインプレースで差し替わります）。新規プリセットは **プリセット側エンジンの明示設定 > ルートプラグイン明示設定 > 有効な環境変数 > デフォルト値** の順で解決されます。既存プリセットは読み込み時の値を保持するため、ルート設定の変更反映にはプリセットの再読み込みが必要です。ネイティブクライアント slot・リソース宣言・インストール方法は既存インターフェースを踏襲します。

新しい `compact-checkpoint` が出現するたびにターン後小カットは 1 回だけスキップされます。`spine-checkpoint` ではこのスキップは発動しません。

`gate.js` の公式圧縮プリセットはデフォルトで `thresholdRatio: 0.8`、`headroomTokens: 65536`、`retainTokens: 8192` を使用し、起動前に対応する環境変数で上書きできます。これらの値は公式大圧縮のみを制御し、小カット位置には影響しません。

クラウドのデフォルトはアドレスにかかわらず `0.8`・`65536`・`8192` のままです。TUI の `/settings` にはこの項目はありません。`cordis.patch.yml` 自体は環境変数を展開せず、未記入のフィールドはエンジンが環境変数およびデフォルト値で補完します。設定ブロックに直接記入した明示値が優先されます。例:

```yaml
- id: compaction-spine
  name: dsh-live-compact
  config:
    auto: true
    thresholdRatio: 0.8
    headroomTokens: 16384
    retainTokens: 8192
    compactionRetries: 0
```

## インストール

npm からインストールします。`headless` と `web` は別々のプロファイルのため、それぞれインストールが必要です。Desktop は別プロファイルであり、通常の `dsh plugin --profile desktop` は拒否されます。

```sh
dsh plugin --profile headless add dsh-live-compact@1.1.14
dsh plugin --profile web add dsh-live-compact@1.1.14
```

先にローカルへ入れてバージョンを確認する場合:

```sh
npm install -g dsh-live-compact
dsh-live-compact --version
```

ミラーからインストールすることもできます:

```sh
dsh plugin --profile headless add https://download.merkyorlynn.com/downloads/plugins/dsh-live-compact-1.1.14.tgz
dsh plugin --profile web add https://download.merkyorlynn.com/downloads/plugins/dsh-live-compact-1.1.14.tgz
npm install -g --force "https://download.merkyorlynn.com/downloads/plugins/dsh-live-compact-1.1.14.tgz"
dsh-live-compact --version
```

DSH `>=0.2.0-rc.2 <0.3.0` が必要です。インストール後に長時間のタスクを実行し、ログに `spine cut …ms` が出力されればカットが有効に動作しています。配布ページ: https://download.merkyorlynn.com/live-compact.html

DSH-TUI にはまだインストールしないでください。TUI v0.20.0 では `spine-checkpoint` 部分カードの表示に対応していますが、本パッケージが現在圧縮を引き継ぐのは Web および Desktop プリセットのみで、TUI プリセットは純正圧縮のまま動作します。引き継ぎ対応と結合検証の完了後にサポートを開放予定です。

カットされた原文は `~/.dsh/compaction-spine/shadow` に保存されます。Unix 権限はディレクトリ `0700`・ファイル `0600`、Windows で新規作成／修正されたバックアップは現在のユーザー・`SYSTEM`・`Administrators` を許可します（旧ファイルおよびキャッシュ制限は上記の ACL 説明を参照）。上限は 256MB で、上限に近づくと最も古いバックアップから削除されます。カード内の番号はセッションログのイベント番号です。現在のセッションのバックアップ内を検索したい場合は `import { searchShadow } from "dsh-live-compact/shadow-search"` を利用してください（プラグイン自身が自動検索することはありません）。

`spine-maintenance.jsonl` は既存の shadow ディレクトリ内にターン終了時のメンテナンス状態を記録します。同一の `operation` が 1 回の試行に対応し、`deferred` は補完キャプチャ未完了、`completed` の `cuts` はその回に確定した小カット数を表します。ホストがモデル圧力予算を拒否した場合、その設定理由が `spine-decisions.jsonl` に記録されます。

`dsh-live-compact stats` の `saved` はカット直後に削減されたトークン数、`rewrite` は同一ドレインで実際に書き換えが必要になる末尾トークン数（1 ドレインにつき 1 回だけ計上し、カット回数で掛け算しません）です。両者は集計基準が異なるため、比率は単純な損益ではありません。Desktop には端末がないため、`rg "spine cut"` が使えるのは端末出力のみです。各 shadow ルートの `spine-cuts.jsonl` は直近の完全なカット明細を最大 1 MiB まで保持し、累計カウントは `spine-stats.json` に記録されます。

POSIX 環境のバックアップディレクトリを置くファイルシステムは、実際に `0700`/`0600` 権限を強制できる必要があります。プラグインはディレクトリとファイルの権限を読み戻し、一致しない場合は本文書き込み前にバックアップを拒否します。

上限を変更する場合:

```sh
export SPINE_SHADOW_MAX_BYTES=67108864
```

手動で削除する場合:

```sh
rm -f ~/.dsh/compaction-spine/shadow/*/*.txt ~/.dsh/compaction-spine/shadow/*.txt
```

`DSH_HOME` または `SPINE_SHADOW_DIR` を設定している場合、保存先はそのディレクトリになります。古いファイルを削除できず空き容量を確保できない場合、そのカットは実行せず 1 セッションにつき 1 回だけ警告を出します。

デフォルトディレクトリ（`DSH_HOME` 配下を含む）および排他宣言のないディレクトリでは、旧バージョンの writer と安全に共用できるよう毎回フルローテーションスキャンを実行します。`SPINE_SHADOW_DIR` を設定するだけでは推定最適化は有効になりません。スキャン回数を減らしたい場合は、**専用のローカルディレクトリ** を `SPINE_SHADOW_DIR` に指定したうえで `SPINE_SHADOW_SINGLE_PROCESS=1` を併せて設定してください（デフォルトディレクトリを明示指定しても有効にはなりません）。この宣言は、ディレクトリ全体を本プロセスのこのプラグインインスタンスのみが排他利用することを前提としており、旧版 writer・協調プロトコルに従わない writer・ディレクトリツリーや本文を外部から書き換えるプログラムとは共用できません。カスタムコードから下位バックアップ関数を呼び出す場合も、セッションサブディレクトリではなく常に同一の `root` を渡してください。この契約を満たせない場合はデフォルト設定のまま運用してください。

専用ルートで初回フルスキャンを完了した後、ディレクトリ実体・容量上限・所有権が変化しておらず、推定使用量が 80% 未満かつ前回の完全キャリブレーションから 60 秒未満である場合に限り、本文の走査を省略します。60 秒を過ぎると次回のローテーション時に再スキャンします（バックグラウンドの定期クリーンアップはありません）。ファストパスでの返却や書き込みによって有効期限は延長されず、時計の異常や巻き戻しが発生した場合もフルスキャンへ戻ります。スキャン不完全または計測値不正の場合は、容量審査が必要なバックアップを拒否して原文を保持し、過小計上された数値で通すことはしません。

通常ロック経路では、すべての通常 raw/cut/official 書き込みがまずルートでアトミックロックを取得して協調マーカーを確認し、cut/official の容量チェックと本文書き込みも同じクリティカルセクション内で実行します。容量計上は UTF-8／Buffer の実バイト長を保守的に加算し、上書きや失敗時の後始末で安易に減算せず次回フルスキャン時に補正します。raw は従来どおりのキャプチャ規則に従い、書き込み自体ではローテーションを発動しません（連続した raw 書き込みで一時的に上限を超えた分は次回ローテーションで処理されます）。容量対象は本文サイズのみで、付随する meta・owner・統計・ロックファイルは含まず、ディレクトリ全体の物理ディスク使用量のハードクォータではありません。超大型バックアップ例外・削除順序・参照保護も従来どおりです。他セッションのディレクトリは所有プロセスの終了が明確に確認できた場合のみ削除し、権限不足や owner 状態不明時は保守的に残します。通常の cut/official の容量スキャン・削除・公開トランザクションは管理下 worker でルートごとに直列実行され、アイドル worker は自動回収されます。共有ディレクトリでは推定スキップを行わず毎回フルスキャンします。下位の同期 API および raw キャプチャはそれぞれの同期セマンティクスを維持します。

`.spine-rotation.owner` は PID とランダムなライフサイクル識別子を保存します。`shared` フェンスが存在せず、記録形式が正常かつ旧 PID の死亡が明確に確認できる場合のみ、新しいライフサイクルが安全に所有権を再構築してフルスキャンを再実行できます（死亡を確認できない場合は奪取しません）。2 つ目の参加プロセス・worker・プラグイン複製（パスエイリアスを含む）は本文書き込み前に `.spine-rotation.shared` を作成し、以降そのルートは別プロセス終了後も推定へ自動復帰せず常にフルスキャンへフォールバックします。このマーカーは協調する writer 同士のみを検出し、旧版や外部 writer は検出できません。ロックは同一ディレクトリ内の一時ファイルへ完全書き込み・フラッシュ・クローズした後、アトミックなハードリンクで `.spine-rotation.lock` として公開され、保持者 PID とトランザクション固有のランダム ID を含みます。公開成功後に一時ファイル名の削除が失敗してもロックの厳密な所有権は失われず後続バックアップも阻害しません（ローテーション対象外の一時名が残留する可能性はあります）。

ハードリンク操作自体が `ENOTSUP`・`EOPNOTSUPP`・`ENOSYS` を返した場合に限り、`shared` フェンスをフラッシュして先行するアクティブ／潜在的排他トランザクションが存在しないことを確認したうえで、従来のフルローテーションと raw/cut/official/カーソル書き込みを許可し、そのルートでは排他推定を無効化します。本文書き込み前にもフェンスとロック状態を引き続き検証します。`EPERM`・`EACCES`・`EIO`・`EXDEV`・`EINVAL` などの曖昧なエラーや、別ステップでの unsupported エラー時は今回のバックアップを拒否します。このフォールバックは従来の共有並行セマンティクスを踏襲し、排他的な容量保証は提供しません。

アクティブなロック、PID の再利用、旧版の空ディレクトリロック、破損レコード、または死亡確認不能時は今回のバックアップを拒否して原文を保持します。ロック経過時間による奪取は行わず、`EPERM` や未知エラーも死亡とはみなしません。`process.kill(pid, 0)` が明確に `ESRCH` を返した場合のみ、`shared` マーカーを永続化して推定値をクリアし、そのロックの完全な識別情報を `.spine-rotation.recovered` へアトミックに記録します（ハードリンク非対応環境では半端な JSON を避けるため `.spine-rotation.recovered-<pid>-<トランザクションID>` という空ファイルの完全名で記録・フラッシュします）。元のロックはフェンスとして削除・置換せずに残し、以降すべての協調インスタンスはその死亡確認済み識別情報に対して従来のフルローテーションと本文書き込みを行います（後から PID が再利用されても死亡確認済みの事実は変わりません）。復旧後の共有操作は従来の並行セマンティクスに従い、排他容量クリティカルセクションは提供しません。マーカーファイルはすべてディスクへフラッシュし、POSIX ではディレクトリも fsync します（Windows の Node API ではディレクトリハンドルを fsync できないため、突発的な電源断時のディレクトリエントリ永続性は保証しません）。

残留ロックのない正常な再起動時は、形式が有効かつ PID の死亡が明確に確認できる owner のみ再構築可能です。旧版の PID なし owner、既存の `shared` フェンス、確認不能なレコードは保守的にフルスキャンへフォールバックします。メインスレッドと worker のライフサイクル差でも `shared` が立つ場合があるため、本スイッチは本番のすべての書き込みで推定が使われることを保証するものではありません。排他推定を手動で再有効化したい場合は新しい専用ディレクトリを選ぶか、すべての利用プロセスが停止していることを確認したうえで該当ルートの `.spine-rotation.lock`・`.spine-rotation.owner`・`.spine-rotation.shared`・`.spine-rotation.recovered` およびトランザクション固有の recovered 空ファイルを削除してください。旧版の空ロックなど曖昧なレコードも、全利用者の停止を確認したうえで手動処理してください。プロトコルに従わない旧版 writer と共用する場合は、専用ディレクトリ契約を宣言しないでください。
